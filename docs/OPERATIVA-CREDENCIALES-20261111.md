La presencia de fuentes internacionales como MeteoAlarm no reemplaza verificar el aviso primario AEMET; la UI debe identificar cuándo funciona solo como fallback.

**AEMET.** Obtener una API Key nueva mediante el procedimiento oficial, con vencimiento cada **tres meses** según los cambios anunciados por AEMET en julio–octubre de 2026. Guardarla exclusivamente en `Settings > Secrets and variables > Actions > AEMET_API_KEY`, nunca en variables públicas, commits, notas ni logs. Comprobar el resumen de presencia de `deploy.yml` y después `aemet_cap=ok` junto con tiempos/autoridad de la fuente, sin imprimir la clave. Registrar vencimiento fuera de Git y renovar con margen; cuando falle la API se publica explícitamente `sin_clave` o `error`, no un aviso AEMET inventado.

**EUMETSAT MTG-LI.** Decisión: **no configurar claves ni declarar cobertura eléctrica en vivo** hasta confirmar licencia y disponibilidad de producto Lightning Imager Level-2, credenciales (y su expiración), cuotas, latencia en producto, precisión espacial, qué se permite redistribuir y los indicadores de calidad. Pueden requerirse licencias adicionales para determinados datasets del Data Store. La familia eléctrica debe permanecer separada de lluvia y el estado `UNKNOWN`/sin cobertura no puede rebajarse a «sin rayos». Permiso concreto y validación con rayos conocidos → nueva PR controlada; sin ellos, mantenerlo fuera del alcance operativo público.
